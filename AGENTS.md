# AI Builder Cup development instructions

- Product name: Aide. This repository owns the GCP hackathon web/API and GCP-only Android client. AWS, On-Prem, Azure, company SSO and company workers remain outside this repository.
- Restore context through `docs/STATUS.md`, `docs/NEXT_PLAN.md` and `docs/HACKATHON_PLAN.md`. The user resumed development on 2026-10-10 for the AI Builder Cup submission (deadline 18 Oct 2026): an AI agent app, not deterministic runbooks. The product name is a working title; the UI reads it from `apps/web/src/brand.ts`.
- Layout: `apps/web` (console), `apps/gateway` (TypeScript API), `apps/crew` (Python agents), `apps/android`, `apps/shop-api` (demo target), `packages/contracts` (shared schemas, imported as `@contracts/*`), `design`, `deploy`, `docs`, `scripts`, `tests`. Each app has a README; `docs/README.md` indexes the documentation. Build output goes to `dist/` and is never committed. New TypeScript files must be reachable from `tsconfig.json` (`files` is explicit).
- Preserve Korean/English UI via `apps/web/src/i18n.tsx`. Language never selects identity, owner, workspace or permissions. Submission editing and English documentation remain separate work.
- Node.js 24+, React/TypeScript/Vite and Google Material Web (`@material/web`, Material 3). Import each component separately. `design/tokens.json` is the single source for web CSS and the Android color scheme (`npm run generate:tokens`; `make check` verifies it). Install dependencies before checks; `make check` is offline/synthetic and must not install dependencies. `make check-android-core` uses already-prepared Gradle dependencies without installing Android SDKs.
- Server-verified identity/owner/workspace/roles are mandatory. Never deserialize a trusted context from client mode/role/context. Native no-Origin exceptions apply only to the dedicated GCP mobile routes, with bearer and scope checks intact.
- Fixed registered Cloud Run UID/revision and bounded telemetry only. Readiness, query success, coverage and service health are separate. Missing/empty/partial evidence must not become observed zero or healthy. Agents choose among typed tools; they never receive credentials, generate execution code or change IAM. Reads may be autonomous within bounded scopes; any change needs a Guardian verdict and, when risky, a human decision on the phone.
- Review/refresh/replay never starts execution. Execute only explicit server-validated plans with current evidence, identity, membership, version, digest and deadlines. Unknown dispatch/expiry is never automatically resent.
- External calls must stay outside retryable store transactions. SQLite is local/test support, not Cloud Run durable storage. Runtime remains disabled without explicit configuration. Use synthetic data for tests and captures.
- Notification token addresses are private records, excluded from workflow/audit/public payloads. Requests may be retired before registration acknowledgement. Older generations cannot revoke newer ones. Accepted transport is not device delivery. Actual push/source/authority integration remains incomplete.
- Credentials, real resource IDs, account observations, `.data`, `.env`, signing keys, Google configuration and machine caches must not enter Git/reports. Do not inherit the original personal AWS CLI session. Do not add a public notification send endpoint.
- The user authorized in-session on 2026-10-10: the Android SDK and its licenses, Docker and Cloud Build, a Cloud Run deployment and Firebase/Firestore use in the active gcloud project, and real Gemini and Google API calls for this app. Not authorized unless asked again: commit/push, creating a GitHub remote, IAM changes beyond the dedicated runtime service account, deleting cloud resources, publication and submission.
- Keep `docs/provenance/source-manifest.json` as the immutable initial extraction record; it describes a mixed worktree, not a released revision. A new Git history is not proof of a fresh eligible project. Preserve source/asset/dependency attribution. Do not copy pre-program projects or company materials into this repository: the competition accepts only work built inside its window (7 Sep – 18 Oct 2026), and the user's older projects predate it. Reuse ideas, not code.
